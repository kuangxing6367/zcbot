# 多语言（界面语言）

ZCBOT 支持切换**面向用户的提示文案**语言。目前覆盖启动 / 停止等生命周期日志，
切换后无需改代码、重启即生效。

## 支持的语言

| 代码 | 名称 | 基调 | 启动文案示例 |
|------|------|------|--------------|
| `zh` | 简体中文（**默认**） | 正式、简洁 | `ZCBOT 框架 启动中...` |
| `ciallo` | 中文活泼版 | 俏皮、带颜文字 | `Ciallo～(∠・ω< )⌒☆ ZCBOT 框架启动中咯～ 稍等一小下，马上就好喵～` |
| `en` | English | 正式、简洁 | `ZCBOT framework starting...` |

> **关于 Ciallo～**
> 「Ciallo～(∠・ω< )⌒☆」是柚子社 galgame《魔女的夜宴》女主角**因幡巡**的标志性问候语，
> 由意大利语「Ciao」与英语「Hello」合成，配上配套的卖萌颜文字，是中文 ACG 社群里
> 辨识度极高的活泼打招呼用语。这里只把它作为「活泼版」的语气基调——**只改语气，不改事实**。

## 三种设置方式（优先级从高到低）

### 1. 启动参数（优先级最高）

```bash
python main.py --language ciallo
python main.py -l en              # 简写
python main.py --language=ciallo  # 等号写法
```

### 2. 环境变量

```bash
ZCBOT_LANG=ciallo python main.py
```

适合容器 / systemd 等不方便改参数文件的场景。

### 3. config.yaml（持久生效）

```yaml
language: ciallo    # zh（默认）/ ciallo / en
```

首次启动自动生成的 `config.yaml` 里已包含该项（默认 `zh`），改完重启即可。

> 优先级：**启动参数 → 环境变量 `ZCBOT_LANG` → `config.yaml` 的 `language` → 默认 `zh`**。
> 三种方式可以混用，临时调试用参数、长期用配置文件。

## 实际效果

```
# --language ciallo
INFO ==================================================
INFO Ciallo～(∠・ω< )⌒☆ ZCBOT 框架启动中咯～ 稍等一小下，马上就好喵～
INFO ==================================================
INFO Ciallo～(∠・ω< )⌒☆ 启动完成啦～ 正竖起耳朵等你的消息哦～（总共花了 3.31s）

# --language en
INFO ZCBOT framework starting...
INFO Framework started, waiting for messages... (took 3.90s)

# --language zh（默认）
INFO ZCBOT 框架 启动中...
INFO 框架启动完成，等待消息...（总耗时 3.20s）
```

## 覆盖范围

当前已本地化的文案：

| 词条 key | 时机 |
|----------|------|
| `framework.starting` | 框架启动开始 |
| `framework.started` | 框架启动完成（含耗时占位符 `{elapsed}`） |
| `framework.stopping` | 框架停止开始 |
| `framework.stopped` | 框架已停止 |

框架其余日志（插件加载、数据库连接、安全策略等）仍为中文 —— 它们是**运维诊断信息**，
不是面向终端用户的提示，刻意保持单一语言以避免跨语言排查困难。

## 给插件开发者

插件可以直接复用同一套 i18n 能力给用户返回本地化文案：

```python
from framework import i18n

i18n.set_language('ciallo')                      # 通常不需要：跟随框架全局设置
i18n.t('framework.starting')                    # → Ciallo～(∠・ω< )⌒☆ ...
i18n.t('framework.started', elapsed='1.23')     # 支持 {} 占位符
```

新增词条：在 `framework/i18n.py` 的 `LANGS` 里为 `zh` / `ciallo` / `en` 各加一条即可。

### API

| 函数 | 说明 |
|------|------|
| `i18n.t(key, **kwargs)` | 取本地化文案，支持 `{}` 占位符 |
| `i18n.set_language(lang)` | 设置语言，返回实际生效代码（无法识别时回退 `zh`） |
| `i18n.get_language()` | 当前生效的语言代码 |
| `i18n.available_languages()` | 所有支持的语言代码 |
| `i18n.normalize(lang)` | 归一化写法（`zh_CN` / `en_US` / `CIALLO` → 标准代码） |

## 设计约定与坑

1. **协议标识符不翻译。** 例如调试控制台的 `'ZCBOT console'` banner 是进程探测用的
   协议字段，翻译会破坏「已有控制台在跑」的探测逻辑与相关测试断言。只翻译给人看的文案。
2. **缺失必回退，绝不抛异常。** 取词顺序是「当前语言 → `zh` → key 本身」；
   占位符填充失败时原样返回模板 —— 启动日志不能因为文案问题把框架带崩。
3. **不引入 gettext / .po / .mo。** 用纯 Python 词条字典，免编译、改完即生效，
   适合「文案随版本走、不随系统 locale 走」的场景。
4. **启动参数会被提前摘出。** `--language` / `-l` 在进入子命令解析前就被摘掉并同步回
   `sys.argv`，否则会被下游当成配置文件路径（同类历史坑：`python main.py argparse`
   曾生成一个叫 `argparse` 的默认配置）。
