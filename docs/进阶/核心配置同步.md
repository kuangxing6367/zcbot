# 核心插件配置：文件与数据库的同步

`data/core_plugins.yaml` 是官方插件的启停与配置清单。从 1.28.15 起它同时镜像进
`core_config` 表，规则只有三条。

## 一、谁说了算

| 场景 | 行为 |
| --- | --- |
| 手改 `core_plugins.yaml` 后重启 | **文件赢**：内容全量覆写 `core_config`，敏感键加密落库 |
| 面板里改某项配置 | 写 `core_config`（`source='panel'`）**并回写** yaml 对应行 |
| 文件内容没变 | 只更新 `synced_at`，不重建行，`id` 不漂移 |
| 文件里删掉的配置项 | 库里同步消失（全量覆写，不是合并） |

启动时的同步入口是 `framework.core_config_sync.sync_and_annotate()`，由
`Framework.__init__` 在建库之后调用一次；数据库降级模式与双进程宿主模式（RemoteDatabase）
下跳过，不阻断启动。

## 二、文件里会多出什么

首次同步会给文件加三类元信息，**不动你已有的键、值与注释**：

```yaml
# ===== ZCBOT 核心插件配置（core_plugins.yaml） =====
# 此文件是核心插件配置的权威来源。直接修改后重启框架，内容会自动覆写数据库。
# 面板修改会同步写回本文件；每项 "# id:N" 对应数据库 core_config 表主键。
# 敏感凭据（token/api_key/app_secret）在库中加密存储，接口一律显示 ***。
# =====

# synced_at: 1795680149
core_plugins:
  qq_official:
    enabled: false  # id:75
    app_id: ''      # id:76
```

`# id:N` 是 `core_config` 主键，`synced_at` 是最后一次同步的 unix 时间戳。
两者都只是注释，删掉不影响解析，下次启动会补回来。

## 三、敏感值怎么存

- 落库：`token` / `access_token` / `app_secret` / `api_key` / `secret` 等键以
  `enc:v1:` 密文写入 `core_config`（`framework.secretbox`）。
- 密钥：优先环境变量 `ZCBOT_TOKEN_KEY`（或 `ZCBOT_CONFIG_SECRET`）；没设时框架自动在
  `data/config_secret.yaml` 生成一份内置密钥（权限 0600）。
- **配置文件本身不会被自动加密**：只有显式配了 `ZCBOT_TOKEN_KEY` 才把 yaml 里的明文
  凭据一次性加密写回。这样"手写明文 → 重启 → 框架接管加密入库"这条路始终可用。
- 读取：`GET /api/config/core`、`GET /api/config/yaml`、`GET /api/connection`
  对敏感键**一律给 `***`，超管也一样**——凭据只进不出，要改就填新值覆盖。

## 四、面板接口

```text
GET  /api/config/core                      # [{id, plugin, key, value, synced_at, source, sensitive}]
PUT  /api/config/core/<plugin>/<key>       # body: {"value": "..."}
```

`PUT` 收到 `***` 会当作"没改"直接忽略，不会把占位符写成真配置；写入成功同时更新
yaml 对应行、`synced_at` 与 `# id:N`。

## 五、常见问题

**改了面板配置，重启后又被文件盖掉了？**
面板写库时会同步回写文件，正常不会。若手工把 yaml 从备份恢复成旧版本，重启后按"文件赢"
覆盖——这是设计如此。

**`data/config_secret.yaml` 丢了怎么办？**
已加密的凭据无法解密，需要重新填写各接入端的 token / secret。该文件不进版本库，
备份时请一并带上。

**`core_config` 表被删了？**
与其它扩展表一致：按策略不自动重建（避免空表掩盖数据丢失），需要
`database.repair_missing_tables: true` 或从备份恢复。
