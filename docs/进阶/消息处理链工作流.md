# 消息处理链工作流

工作流回答一个问题：**这条消息进来之后，哪些插件参与、按什么顺序参与**。

框架默认只有一条链路——事件进入后按插件优先级（`/api/plugins` 里的 `priority`）依次
尝试命令匹配，未命中再广播 `message` 事件。这条链路不变；工作流提供的是「按 QQ 号
切换到另一条节点链」的能力。

## 启用编辑器

`core_plugins/workflow_editor` 是官方插件，默认关闭。在 `core_plugins.yaml` 打开：

```yaml
core_plugins:
  workflow_editor:
    enabled: true
```

打开后 WebUI 侧边栏出现「工作流编辑器」。页面用自包含 HTML/CSS/JS 实现，不依赖
闭源前端产物的分包。读写都走 `/api/workflows` 系列接口，复用登录鉴权、super 写权限
与审计。

## 节点类型

节点按数组顺序执行：

| 类型 | 作用 | 配置 |
| --- | --- | --- |
| `user` | 只让指定 QQ 继续往下走；没点名则整条链不生效，退回默认 | `{"values": ["123456"]}` |
| `group` | 只让指定群号继续；私聊群号为空 | `{"values": ["1001"]}` |
| `plugin` | 把插件加入本次允许集合，按出现顺序排列（同一插件只记一次） | `{"plugin": "echo"}` |
| `exclude` | 从允许集合移除插件，优先级高于 `plugin` | `{"plugin": "echo"}` |
| `stop` | 节点链到此结束，后续节点不执行；已选中的插件仍参与 | `{}` |

没有绑定工作流、或节点数组为空时，返回"无计划"：全部插件按原优先级参与，
行为与改造前一致。

## 按 QQ 选择

`workflow_bindings` 表保存 QQ 号到工作流的映射：

- 精确匹配 `user_id` 的绑定优先；
- 没命中时若有 `is_default=1` 的工作流，使用默认链；
- 两者都没有，走框架默认链路。

默认工作流只有一条：通过面板设置 `is_default` 时会自动清掉其它工作流的该标记。

## 影响范围

工作流在两个位置生效：

1. `framework/core/dispatch.py` 的 raw handler 循环：过滤本次不允许的插件；
2. `framework/messaging/router.py` 的命令循环：按节点链重排插件队列。

`message` 广播仍走 `EventBus` 的订阅机制，工作流不复制插件执行逻辑，只决定
"哪些插件有资格参与本次事件"。

## REST 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/workflows` | 登录 | 列出全部工作流 |
| POST | `/api/workflows` | super | 新建（保存前校验节点） |
| GET | `/api/workflows/<id>` | 登录 | 含绑定的 QQ 号 |
| PUT | `/api/workflows/<id>` | super | 更新 |
| DELETE | `/api/workflows/<id>` | super | 删除工作流及其绑定 |
| POST | `/api/workflows/nodes/validate` | 登录 | 节点合法性校验 |
| POST | `/api/workflows/preview` | 登录 | 给定 QQ 预览命中的插件顺序 |
| POST | `/api/workflows/generate` | super | 按 QQ 列表与插件列表生成节点数组 |

所有写操作都写 `audit_logs`，动作名为 `workflow_create` / `workflow_update` /
`workflow_delete`。

## 数据存放

`workflows`（节点 JSON + 启停 + 默认标记）与 `workflow_bindings`（QQ 绑定）两张表
由 `framework/database/schema.py` 在启动时以 `CREATE TABLE IF NOT EXISTS` 建立，
不需要额外迁移。运行时通过 `WorkflowStore` 的 5 秒 TTL 内存快照读取，管理面写入后
立即 `invalidate()` 让新配置生效。

## 文件管理强化

`framework/api/files.py` 同时做了三项加固：

- 上传与写入统一后缀黑名单（`.pyc` / `.db` / `.sqlite` / `.db-wal` / `.db-shm`），
  敏感文件也不能上传；
- 在线预览限制 2MB，上传单文件限制 16MB；无 `Content-Length` 的分块上传在落盘后
  按实际大小兜底检查；
- `content_length` 为 `None` 时不再抛异常。
