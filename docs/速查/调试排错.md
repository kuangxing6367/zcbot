# 调试与测试（给 LLM）

## 跑测试

```bash
# 全量 pytest(与 CI 同一条命令,不列文件名)
python -m pytest tests --ignore=tests/db_conformance -q

# 脚本式回归(断言写在 check() 里、失败 sys.exit 的文件)
# 清单由静态分析自动发现,不用手动枚举;新增测试文件自动纳入
python tools/run_script_tests.py
python tools/run_script_tests.py --list    # 只看判定结果
python tools/run_script_tests.py --check   # 用例数不得低于基线

# 多后端一致性套件(sqlite;接 MySQL 时加 --db mysql)
python -m pytest tests/db_conformance -q

# 单个文件
python -m pytest tests/test_smoke.py -q
```

为什么不能只跑 `pytest tests/`:有两类文件在 pytest 下会假绿——没有 `def test_*`
的文件收集 0 例(整个文件不执行),有用例但函数体零 `assert` 的文件永远 PASS。
`tools/run_script_tests.py` 用 AST 判定这两类并逐个执行。

CI(`.github/workflows/tests.yml`):py3.10–3.13 正式矩阵 + 3.14 观察 = 脚本式回归 +
全量 pytest + DB 一致性 + 覆盖率归档;`windows-smoke` 作业做 Windows 冒烟;
`ci.yml` 只做多版本 compileall + 启动冒烟 + WebUI 产物校验;
`build-zcbot-render.yml` 编译原生扩展(仅 native/** 变更);`deploy-docs.yml` 部署文档站。

### IIPC 链路基准(`framework/iipc/tools/`)

```bash
python framework/iipc/tools/run_all_bench.py              # 全跑(含 go/cargo 编译)
python framework/iipc/tools/run_all_bench.py --skip-build  # 只跑基准
python framework/iipc/tools/run_all_bench.py --only e2e,stress
python framework/iipc/tools/stress_check.py --soak-n 1000  # 加大吞吐样本看是否线性
```

脚本(e2e 25 / official 32 / surface 154 / adapter 13 / stress 16 + latency)**端口全部动态分配**
(`framework/iipc/tools/portutil.py`,bind :0 向 OS 要空闲端口),不会抢本机正在跑的 WebUI(:8080)或
OneBot 反向 WS(:6830)。要固定端口才设 `ZCBOT_E2E_ADDR` / `ZCBOT_OFFICIAL_ADDR` / `ZCBOT_SURFACE_ADDR`。

性能**三个口径互不替代**,末尾汇总里分开报:① 轻载延迟(起点取**入队时刻**,不是取出时刻)
② 饱和吞吐(按**端到端 span** 算,不是首尾回复时间差) ③ 丢失率 + 15s 级卡顿检测。

## 症状 → 排查

| 症状 | 先查 |
| ---- | ---- |
| 插件没加载 | `core_plugins.yaml` 开关;日志「官方插件 [x] 已加载/加载失败」;目录里有 main.py |
| 客户端看着正常、机器人完全没反应 | 消息首尾的隐形空白(全角空格 / 零宽字符,见 [事件对象 · 七](../接口/基础/事件对象.md#七消息匹配与文本规范化));仍无反应就临时开 `framework.audit.unmatched_events: true`,看审计里有没有 `message_unmatched` |
| Web 后台随机转圈 / 白屏 / 局部超时 | 先看 `ip_blacklist` 里有没有自己(蜜罐误伤,解除见 [安全加固](安全加固.md));再开 DevTools 看首屏传输量与 304 |
| 每次启动都在迁移 / `--inspect` 永远有待办 | 根目录是否还留着 `config.yaml` / `core_plugins.yaml` / **有内容的** `plugins/`;`plugin.dir` 是否把插件目录钉在仓库根([配置系统 · 插件相关](../指南/配置系统.md));账本 `data/.zcbot-state-migration.json` 的状态 |
| 命令不触发 | pattern 是否含正则元字符(决定前缀/正则);`is_dynamic=1` 不参与匹配;别名逗号分隔;插件 priority |
| 命令被吞 | 某插件 raw handler 返回 True 接管了(session 插件等待中的用户) |
| 回复发不出 | 无可用接入端;`adapter_for_source` 按事件来源选端,多端并存不串线 |
| 消息没日志 | `config.yaml → log.log_raw_message` |
| 内存堆积 | 事件缓冲 `EventBuffer.stats()`(l1/l3 字节、sqlite 积压、丢弃计数);workers 默认 1,慢 handler 会排队 |
| Web 500 | http_api 群管等走 `api.acall` 并查 `status`,失败不假报成功 |
| 插件加载报错 | 看启动日志:缺依赖会有中文诊断 + `pip install` 命令;依赖来源见 [插件加载机制 · 六](../进阶/插件加载机制.md) |

## 插件加载失败:平台化诊断

插件加载(用户插件在 `framework/loader/lifecycle.py`、官方插件在 `framework/core/runtime.py`)一旦抛异常,框架不再只甩英文堆栈,而是先经 `framework/deps/diagnose.py` 的 `classify_load_error(exc)` 归类,日志同时输出:**中文诊断 + 安装命令 + 原始错误**。

| 原始报错特征 | 归类 | 日志会提示 |
| ---- | ---- | ---- |
| `No module named 'aiohttp'` 等 | 缺失依赖 | 检测到可能存在依赖缺失,可使用 `<解释器> -m pip install aiohttp` 安装模块;后面附原始消息 |
| `cannot import name 'X' from 'Y'` | 版本不兼容 | 可能是依赖版本不兼容,请核对 `Y` 的版本要求 |
| `ImportError: DLL load failed` / `.so: cannot open` | 系统运行库缺失 | 可能是系统运行库(如 VC++ / libssl)缺失,请先安装对应运行库 |

要点:

- 安装命令里的 `<解释器>` 就是**框架运行所用的 Python**(包管理器经 `sys.executable -m pip`,即当前解释器自身,非 uv / pipx),确保装到正确环境、不会装到别的 Python;
- 未匹配上述模式的异常不会被改写,原始消息原样保留,不会丢失线索;
- 缺依赖时框架默认仍会先自动补装并重试一次(见 [插件加载机制 · 六](../进阶/插件加载机制.md)),诊断提示是补装失败后的兜底说明。

## IIPC 链路排查(`python startup.py --iipc`)

> 端口/DB/管理员:改 `config.yaml` 的 `iipc:` 段(优先级 命令行 > config > 环境变量 > 默认),
> 别去改代码里的默认值。

| 症状 | 先查 |
| ---- | ---- |
| 命令没命中,但消息被广播了 | **这是正确行为**:命令命中后不广播 `message`(对齐 `router.py`)。查 pattern 是否被判成正则(含正则元字符按 re 处理)、富媒体是否被拼进提取文本 |
| handler 跑了但 `send_msg` 静默不发 | **插件进程的 stdout 不进内核日志**,`AttributeError` 之类根本看不到。让插件自己落一个日志文件再看;先怀疑 Event 属性缺失(如 `is_group`) |
| 权限判断一律 False | 分清两个 API:`ctx.has_perm(uid, node)` **不传 role 本来就是 False**(原框架 `perm.resolve` 只做 `ROLE_TO_GROUP.get(role or '')`,不查 users 表);`Event.has_perm` 必须注入自身 role |
| 整条链路卡 15s 才回 | `api.call` 没拿到 echo 响应 → 内核干等 `defaultCallTimeout=15s`。假 OneBot 必须**每个 api.call 都带 echo 应答**(与 `qpsbench.py` 同口径) |
| 突发下间歇卡顿(轻载测不出) | 适配器需先登记 echo 再发请求(pending.insert 在 send **之前**),反序会在高并发下丢响应 |
| 适配器反复重连 / 握手失败 | 反向 WS 取 `Sec-WebSocket-Key` 是否正确;`wss` 不被支持,需前置反代 |
| 吞吐数字忽高忽低 | 口径错了:延迟取**入队时刻**、吞吐取**端到端 span**;用「首尾回复时间差」会虚高一个量级 |
| 端口被占 / 连到别的进程 | 测试脚本默认动态端口;固定端口用 `ZCBOT_*_ADDR`;业务端口改 `config.yaml` 的 `iipc.ipc_addr` / `iipc.onebot_listen` |
| 插件依赖 `ctx._framework` | 内建服务型插件(如 `core_plugins/scheduler`、`session`)跑不了,IIPC 插件在独立进程没有 `_framework`;只能拖 `plugins/*` 用户态插件 |

## 日志

`data/logs/zcbot.log`;启动成功标志:`框架启动完成，等待消息...`;后台
`http://127.0.0.1:8080`(admin/admin123,首次必改密)看仪表盘/日志/在线改配置。
IIPC 链路日志走同一出口(`config.yaml → log:` 段),内核/协议端/插件输出统一汇总到启动器;
**插件自身异常需插件落文件**,不会出现在内核日志里。

想查「谁执行了什么命令、被谁拒绝了」不要翻日志,查 `audit_logs` 表(后台审计页 /
`GET /api/audit_logs`):`command_exec` / `command_denied` / `command_blocked` /
`message_unmatched` 四类,配置见 `framework.audit`。审计是旁路写入,队列满会丢条,
判断完整性看 `AuditWriter.stats()` 的 `dropped`。详见
[可观测性与运维 · 操作审计](../进阶/可观测性与运维.md#操作审计audit_logs)。
